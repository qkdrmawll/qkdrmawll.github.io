## 발표의 핵심 메시지

이번 발표의 콘셉트는 조금 특이했습니다.
바로 **"발표자인 저는 .NET을 잘 모른다"** 는 사실을 그대로 활용하는 것이었어요.

> "저는 .NET을 모릅니다. C#도 모르고, Blazor가 뭔지도 몇 주 전까지 몰랐어요.
> 그런데 오늘 Blazor 앱을 여러분 앞에서 만들 겁니다.
> 여러분이 저보다 훨씬 잘 할 수 있다는 걸 보여드리려고요."

즉, ".NET 전문가가 아닌 사람도 GitHub Copilot App으로 Blazor 앱을 만들 수 있다면, .NET 개발자인 여러분은 훨씬 더 잘 쓸 수 있다"는 메시지를 전하는 것이 목표였습니다.

## GitHub Copilot App이란?

가장 먼저 짚은 것은 **GitHub Copilot App은 IDE 확장이 아니라는 점**이었습니다.

- VS Code 플러그인이나 JetBrains 확장과는 **완전히 다른 별개의 앱**
- **agent-native 데스크탑 앱**으로, macOS · Windows · Linux 모두 지원
- **Copilot Free를 포함한 모든 플랜**에서 사용 가능 (BYOK도 지원)

특히 **My Work 뷰** 하나에서 연결된 레포의 활성 에이전트 세션, 열린 이슈 / PR, 백그라운드 자동화를 한 화면으로 볼 수 있다는 점이 인상적이라 함께 소개했습니다.

## 알아두면 좋은 핵심 개념 3가지

GitHub를 잘 몰라도 되는 이유를 개념 3가지로 설명했습니다.

- **Worktree** — 모든 세션이 자체 git worktree 안에서 실행됩니다. 브랜치의 격리된 복사본에서 작업하기 때문에 같은 레포에 여러 에이전트를 동시에 돌려도 서로 덮어쓰지 않고, 앱이 worktree를 자동으로 생성하고 정리해줍니다.
- **Canvas** — 에이전트와 공유하는 작업 화면입니다. 계획, PR, 브라우저 세션, 터미널, 대시보드 등이 표시되고, 에이전트가 작업하는 동안 실시간으로 업데이트됩니다. 개발자는 같은 화면에서 편집 · 승인 · 방향 수정을 할 수 있습니다.
- **Agent Merge** — PR을 끝까지 책임지는 에이전트입니다. CI를 모니터링하고 필수 리뷰어를 추적하며, 실패한 체크를 처리하고 조건이 충족될 때까지 기다립니다. 어느 단계까지 허용할지는 개발자가 직접 정할 수 있습니다.

## 라이브 데모 — Blazor 날씨 앱 만들기

발표의 중심은 라이브 데모였습니다.
제가 .NET을 아예 모르는 만큼, **모든 결정을 Copilot App에 맡기는 모습 자체**가 메시지가 되도록 진행했습니다.

특히 인상적이었던 점은 두 가지였습니다.

먼저 **이슈를 통해 에이전트와 개발을 기획**하면서, 무엇을 만들지 정리하는 과정에서 좀 더 명확한 개발 지시가 이루어질 수 있었습니다. 막연하게 "만들어줘"라고 하는 대신 이슈에 요구사항을 담아두니 에이전트도 맥락을 잡고 작업하기가 훨씬 수월했어요.

그리고 **worktree와 Agent Merge 덕분에 전반적인 개발 흐름을 Copilot App 내부에서 맡겨서 진행**할 수 있었습니다. 브랜치를 직접 만들고 정리하거나 CI를 붙잡고 있지 않아도, 세션 시작부터 PR, merge까지 이어지는 흐름을 앱 안에서 자연스럽게 이어갈 수 있다는 점이 좋았습니다.

## 에이전트와 함께 일한다는 것

데모 이후에는 "이제 에이전트가 동료"라는 관점에서 에이전트 종류를 정리했습니다.

- **세션 에이전트**: 프롬프트나 이슈에서 시작해 코드를 작성
- **Agent Merge**: PR을 CI 통과부터 merge까지 책임
- **백그라운드 자동화**: 스케줄 / 이벤트 기반으로 조용히 실행

추가로 다른 모델이 계획과 리팩터링 전략을 독립적으로 검토해주는 `/rubber-duck` 커맨드, 외부 툴을 연결하는 MCP 서버, 그리고 .NET을 포함해 7개 언어로 GA된 Copilot SDK도 함께 소개했습니다.

## ".NET만 잘 하면 됩니다"

클로징에서는 예전 방식과 Copilot App을 사용하는 방식을 나란히 비교했습니다.

| 예전에는 | Copilot App으로 |
| --- | --- |
| Git branch 전략 공부 | 세션 시작 → worktree 자동 생성 |
| PR 템플릿 직접 작성 | 에이전트가 diff 보고 PR 초안 작성 |
| Actions YAML 직접 작성 | 워크플로우 설명 → 에이전트가 생성 |
| CI 실패 직접 디버깅 | Agent Merge가 감지 후 자동 수정 |
| Issue → 코드 직접 연결 | 이슈에서 세션 시작 → 컨텍스트 자동 주입 |

그리고 청중분들께 세 가지 액션 아이템을 남겼습니다.

1. GitHub Copilot App 다운로드 
2. 기존 .NET 프로젝트 레포 연결해보기
3. 이슈 하나 만들고 세션 시작해보기

## 발표를 마치며

코파일럿 챗만 쓰다가 코파일럿 앱을 직접 사용해보면서 느낀 편리함을 다른 분들께도 소개하고 싶었는데, 이번 밋업이 그 이야기를 나눌 수 있는 좋은 기회가 되었습니다.

.NET을 잘 모르는 제가 발표를 준비하면서 오히려 "그럼 도구가 얼마나 도와줄 수 있을까"를 더 깊이 들여다보게 되었고, 그 과정 자체가 저에게도 좋은 공부가 되었습니다.

앞으로도 GitHub Copilot과 AI 기반 개발 방식을 직접 사용해보고, 배운 내용을 이렇게 정리해서 나눠보려고 합니다.
좋은 자리를 마련해주신 닷넷 밋업 관계자분들과 발표를 들어주신 모든 분들께 감사드립니다.
